# 桥（gb.dex）编译配方 —— 2026-10-04 实测走通

之前这项一直做不成（2026-10-04 之前没人留下可用的步骤），踩坑记录在下面，照做即可。

## 环境（10.0.0.108：Debian 13 / 20 核，root 免密）

- JDK 21（系统自带 `openjdk 21.0.12.1`）
- build-tools：**必须用 34**（`android-14`）。35 的 URL 404，别试。
  `https://dl.google.com/android/repository/build-tools_r34-linux.zip` → 解压出 `android-14/lib/d8.jar`

## 编译依赖（initrd 里没有，必须自己下）

| jar | 用途 |
|---|---|
| `org/json/json/20231013/json-20231013.jar` | org.json（initrd 里**没有**，只在旧 dex 内） |
| `com/squareup/okhttp3/okhttp/4.12.0` + `okio-jvm/3.6.0` + `kotlin-stdlib/1.9.10` | okhttp3 |
| `com/google/code/gson/gson/2.10.1` | gson |

外加 initrd 里的 Android framework jar：
`find <initrd>/system/framework -name '*.jar' -printf '%p:'`

## 步骤

```sh
cd /root/bs                     # 桥源码（guest/java/src 的内容拷到这里）

CP=$(find <initrd>/system/framework -name '*.jar' -printf '%p:')
for j in /root/buildlibs/*.jar; do CP="${CP}$j:"; done

# ① 只编 bridge + 业务包；**不要**编 android/ dalvik/ ——它们是给 guest 用的桩
rm -rf out && mkdir -p out
javac --release 17 -nowarn -encoding UTF-8 -cp "$CP" -d out \
  bridge/*.java com/github/catvod/**/*.java

# ② 剔除 android/dalvik 桩 class（它们由 framework 提供，塞进 dex 会让 d8 报
#    NullPointerException: Cannot invoke "String.length()"）
rm -rf out/android out/dalvik
(cd out && jar cf ../bridge.jar .)

# ③ d8 转 dex
mkdir -p dexout
java -cp /root/android-14/lib/d8.jar com.android.tools.r8.D8 \
  --min-api 31 --lib <initrd>/system/framework/framework.jar \
  --output /root/bs/dexout /root/bs/bridge.jar
```

产物 `dexout/classes.dex` ≈ 120KB，替换 initrd 里的 `/gb.dex`（旧的是 291KB）即可。

## 踩过的坑（别重复）

| 现象 | 原因 | 解法 |
|---|---|---|
| `error: org.json 不存在` | initrd 里没有该 jar（只存在于旧 dex 内） | 下 `json-20231013.jar` 加进 CP |
| `error: okhttp3 / gson 不存在` | 同上 | 下对应 jar |
| `Unsupported class file major version 61` | 老 d8/dx 不认 Java 17 | 用 build-tools 34 的 d8 + `--release 17` |
| `-source 11 不支持 switch 表达式` | 降版本失败（源码用了 Java 14+ 语法） | 用 `--release 17`（d8 8.2 才认）|
| `d8: NullPointerException "String.length()"` | 编译产物里混进了 android/dalvik 桩 class | 打完 class 先 `rm -rf out/android out/dalvik` |
| `SleepPatcher$1$1.class` 仍报同样 NPE | d8 8.2 对该内部类的已知问题 | **删掉 `bridge/SleepPatcher*.class` 与 `SleepPatchingLoader*.class`**（它只用于反调试，删后桥仍可用）|

## 配套：initrd 重打（也在 108 上，30 秒）

```sh
gzip -dc art_initrd_x64.gz > initrd.cpio
cd rootfs && cpio -idm --no-absolute-filenames < ../initrd.cpio
cp /root/bs/dexout/classes.dex gb.dex
cp /root/init_x86.sh init && chmod 755 init
find . | cpio -o -H newc --owner 0:0 2>/dev/null | gzip -1 > ../art_initrd_x64.gz
```
